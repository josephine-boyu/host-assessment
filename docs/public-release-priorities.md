# 發布品質檢核表

本表供維護者在發布前確認安全與功能邊界；未完成項目應阻擋發布或明確限制支援範圍。產品擴充方向見 [ROADMAP](../ROADMAP.md)，發布操作見 [發布指南](public-release.md)。

## 內容與隱私

- 公開檔案由逐檔白名單控制；不得包含憑證、本機設定、真實報告或私人維運紀錄。
- 匯出器掃描所有列入檔案，拒絕路徑穿越、symlink／junction 與敏感檔名。
- 對最終副本與將推送的 Git 歷史執行獨立秘密掃描，人工檢閱案例與設定的去識別化。
- 文件連結、匿名範例、LICENSE、SECURITY 與指令應可由新使用者獨立理解。

## 分析品質

- counter 依時間排序、去重並辨識 reset；區分視窗尖峰與服務生命週期 high-water mark。
- CPU／RAM、PHP、PSS、HTTP 與 EBS 的 coverage 必須符合各自門檻；缺值、未知或不相容來源不得補零。
- HTTP 來源版本、有效起點與缺口紀錄須可驗證；重新彙整不能補回不存在的資料。
- 每日日期與指定視窗一致，必要事件對應同一主機；EC2 健康異常與已知壓力不得被其他健康指標掩蓋。
- 延遲峰值標明聚合語義；目標容量須有可核對的規格、相容性與來源證據。
- 建議附理由與限制；資料不足須明示，任何試降候選仍需人工審核。

## 主機影響與驗收

- 唯讀盤點與安裝／調校／回滾分離，安裝前檢查不修改主機。
- 明列額外依賴、服務重載、費用、CPU／RAM／I/O／日誌空間及停止方式，見 [安裝影響](installation-and-impact.md)。
- 驗證日誌容量與處理批次限制；超量或漏收須保留缺口，不得誤判為低負載。
- 驗證備份、手動及故障自動回滾、服務狀態與 metadata；不完整備份不得當作有效回復點。
- 執行測試、shell 語法檢查、匿名示範與必要的 [systemd lifecycle 驗收](monitor-lifecycle-validation.md)。
- 明列已驗證的 OS／PHP／Web Server 組合；不得將隔離容器驗收等同所有正式環境已驗證。

## 首版支援範圍

目前以 Linux／AWS 盤點及 AWS WordPress 容量評估為主。GCP、動態價格、自動候選機型、自訂品質門檻及更多 workload 規則屬後續擴充，不是現有功能的承諾。工具不自動修改主機規格或設定。
